# What is AGENTS.md？

本 skill 的唯一目标是**教学与解释**，不提供任何创建或修改 AGENTS.md 的指令。

## 1. 定义

**AGENTS.md 是一个项目级、目录级的规则文件**，用于把“人脑中对项目的隐性理解”外化成可被 AI 直接读取和遵循的显性规则。

它不是普通的项目文档，而是**人-AI 协作的接口协议**。

## 2. 核心作用

- 把原本只存在于开发者脑子里的**开发约束、架构判断、品味偏好、禁止事项**变成 AI 能理解的文本。
- 让 AI 在没有开发者实时指导的情况下，依然能做出**接近开发者本人决策质量**的选择。
- 降低 AI 每次都要从零推理“这个项目该怎么做”的认知负担。
- 把工程文化从“口口相传”变成**可传承、可迭代的显性协议**。

## 3. 技术原理（最核心）

AGENTS.md 的技术核心是两个机制：

### 3.1 自动上下文注入（Automatic Context Injection）
OpenCode / Claude Code 等宿主系统会在启动会话时，自动扫描并把 AGENTS.md 的内容**注入到 system prompt**（或 messages 的最前面），让模型在生成回复前就能看到这些规则。

### 3.2 向上遍历发现（Walk-up Discovery）—— 重点
系统会从当前工作目录开始，**逐级向上**查找 AGENTS.md，直到找到项目根目录或用户主目录。

这意味着：
- 你可以在**任何重要子目录**放置 AGENTS.md
- 子目录的 AGENTS.md 会覆盖或补充根目录的规则
- AI 在进入不同子目录时，会自动获得该目录专属的上下文和约束

**这就是为什么 AGENTS.md 可以实现细粒度、分层的上下文管理**。

## 4. 推荐结构

一个好的 AGENTS.md 通常包含以下层次：

- **根目录 AGENTS.md**：全局架构、初始化流程、核心约束、团队规范
- **子目录 AGENTS.md**：该模块特有的规则、禁忌、决策边界
- **强烈具体的规则**：而非泛泛的“要写好代码”
- **解释“为什么”**：让 AI 理解背后的意图
- **可验证的规则**：能被工具、CI、hook 直接检查的规则

**参考示例**：详见 `references/good-examples.md`，其中提炼了多个高质量项目的共性特征和典型片段。

## 5. 创建原则

- **先理解原理，再写规则**
- **写“决策边界”，而不是“最佳实践”**
- **把历史债务和奇怪设计的来龙去脉记录下来**
- **用强硬、明确的语气表达禁忌**
- **优先写“绝对不能做的事”和“冲突时的取舍顺序”**

## 6. 维护原则

- AGENTS.md 不是写一次就放着，而是**随项目演进而持续迭代**
- 当发现 AI 反复踩坑时，应该把规则补充进 AGENTS.md
- 子目录的 AGENTS.md 应该保持精简，只写该目录特有的规则
- 定期审查是否有过时或冗余的规则

## 7. 常见反例

- 把 AGENTS.md 写成泛泛的“代码规范”文档
- 只写“要优雅”“要清晰”，不写具体判断标准
- 把所有规则都堆在根目录，不利用子目录分层
- 写了一堆模板化的 checklist，没有项目特有的品味和禁忌
- 忽略技术原理，只当它是普通文档

---

**记住**：AGENTS.md 的价值不在于“有”，而在于**真正被 AI 理解和内化**。理解原理，是写好 AGENTS.md 的前提。
